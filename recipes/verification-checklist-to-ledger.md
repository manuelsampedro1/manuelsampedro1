# Verification Checklist to Ledger Evidence

Use this when one tool generates a verification checklist and another tool records the agent run.

## Goal

Turn a suggested verification plan into auditable command evidence before the checks run. The ledger should show planned verification, executed verification, and any remaining gap without relying on prose in the final answer.

## Source Event

This recipe came from `agent-run-ledger` commit `46de281c62f0`, which added `import-checklist` for Markdown checklists generated by `verify-by-change`.

Relevant files:

- `src/cli.js`
- `test/ledger.test.js`
- `README.md`

## Workflow

1. Generate a checklist from the actual changed files.
2. Parse each checklist section as one planned verification event.
3. Treat backtick-only bullets as affected files.
4. Treat the remaining bullets as commands or manual checks to run.
5. Append those entries to the run ledger with `status: planned`.
6. Run the checks.
7. Add executed command evidence or blockers after the run.
8. Use a doctor command to verify that the ledger is parseable and contains command evidence.

## Checklist

- Does the imported event preserve the checklist section title?
- Are file references copied into structured `files` rather than buried in prose?
- Are suggested commands copied into structured `commands`?
- Is the default status honest, such as `planned`, before execution?
- Does the importer have tests for parsing and CLI append behavior?
- Does a smoke test prove the producer and ledger work together?

## Verification

For a local Node CLI paired with `verify-by-change`, run:

```sh
python3 /path/to/verify-by-change/verify_by_change.py README.md src/cli.js --output /tmp/verification-checklist.md
node bin/agent-run-ledger.js import-checklist --ledger .agent-run/ledger.jsonl --checklist /tmp/verification-checklist.md
node bin/agent-run-ledger.js doctor --ledger .agent-run/ledger.jsonl --json
```

Then parse the doctor JSON in a separate command so malformed output fails:

```sh
node bin/agent-run-ledger.js doctor --ledger .agent-run/ledger.jsonl --json > /tmp/doctor.json
node -e 'JSON.parse(require("fs").readFileSync("/tmp/doctor.json", "utf8"))'
```

## Failure Modes

- Importing checklist text as one blob instead of structured events.
- Marking imported checks as passed before execution.
- Dropping file references, which makes review routing harder.
- Letting checklist parsing depend on a fragile exact title.
- Using this as a substitute for actually running the checks.
