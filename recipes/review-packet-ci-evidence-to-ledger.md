# Review Packet CI Evidence to Ledger

Use this when a Codex review packet already contains GitHub Actions evidence and the final handoff needs a durable audit trail.

## Goal

Import embedded `## CI Evidence` from a review packet into `agent-run-ledger` as command evidence instead of copying a loose "CI passed" claim into chat.

## Source Event

This recipe came from updating `agent-run-ledger import-review-packet` to parse CI evidence generated by `codex-review-packet --ci-run`.

The public change lets CI evidence travel from GitHub Actions JSON, into a review packet, and then into a ledger report.

## Workflow

1. Push the repo change and wait for the relevant GitHub Actions run.
2. Fetch the run JSON from the GitHub Actions API.
3. Generate a review packet with `codex-review-packet --ci-run`.
4. Import that packet with `agent-run-ledger import-review-packet`.
5. Run `agent-run-ledger doctor --json` or `doctor --strict`.
6. Confirm the CI command event status matches the run conclusion and the SHA matches the reviewed commit.

## Example

```sh
curl -fsS \
  https://api.github.com/repos/OWNER/REPO/actions/runs/RUN_ID \
  > /tmp/ci-run.json

python3 /path/to/codex-review-packet/codex_review_packet.py \
  --repo /path/to/target-repo \
  --ci-run /tmp/ci-run.json \
  --output /tmp/review-packet.md

node /path/to/agent-run-ledger/bin/agent-run-ledger.js import-review-packet \
  --ledger .agent-run/ledger.jsonl \
  --packet /tmp/review-packet.md

node /path/to/agent-run-ledger/bin/agent-run-ledger.js doctor \
  --ledger .agent-run/ledger.jsonl \
  --json
```

Expected ledger signal:

```json
{
  "title": "CI passed: CI",
  "status": "passed",
  "commands": ["GitHub Actions: CI"]
}
```

## Checklist

- Does the review packet contain `## CI Evidence`?
- Does the CI evidence include run ID, status, conclusion, URL, and SHA?
- Does the ledger command status reflect the conclusion rather than only `status: completed`?
- Are both the review packet and CI source JSON referenced as files?
- Does `doctor --strict` still surface any planned checks that were imported from the same packet?
- If CI failed or is still running, does the ledger preserve that state instead of converting it to success?

## Failure Modes

- Treating a completed run as passed without checking `conclusion`.
- Importing a packet generated from an older commit's CI JSON.
- Losing the run URL when moving evidence from packet to ledger.
- Using chat as the only place where CI evidence is recorded.
- Hiding planned verification checks behind passing CI evidence.
